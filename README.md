# AI-CSRF

注：本人练手项目。

这是一个用于自动化修复 CSRF 风险的项目，目标是做一个面向前后端仓库的 AI CSRF 自动修复插件：自动分析、修复、测试、提交关联 PR，并在检查通过且满足策略时自动合并。

## 目标

1. 接收前后端仓库地址。
2. 分析 CSRF 防护缺口。
3. 生成修复改动与测试。
4. 自动提交 PR，并在满足策略时合并。

项目文档见 `docs/` 目录。

## 目前进展

- 目标 1：已完成。支持接收前后端仓库地址、地址校验、run-id 生成，并已支持仓库准备流程，包括远端访问检查、`clone/fetch` 和工作分支创建。
- 目标 2：初步完成。当前已完成静态规则扫描和规则决策；同时已完成接入 Codex 决策链路（`--ai-decide-fixes`），可基于扫描结果生成结构化修复决策，并在 AI 调用失败时回退到规则决策。
- 目标 3：已完成 MVP。当前已完成后端修复 MVP 和前端修复 MVP：后端支持对 Express CommonJS 项目生成 CSRF middleware、接入入口文件并生成最小测试；前端支持对 Axios 请求封装项目生成 token 读取、header 注入工具、入口接入和最小测试。
- 目标 4：初步完成。已接入 CI 闸门、自动提 PR 和 on-green 自动合并流程，支持输出完整报告链路；在缺少平台 CLI 或权限时会返回手动执行命令。

## 说明

当前阶段默认不会直接修改目标仓库代码，主要是先跑流程。只有显式传入 `--apply-backend-fix` 或 `--apply-frontend-fix`，并且识别到支持的项目结构时，才会在本地工作分支生成修复改动。PR 和合并动作同样需要显式参数触发。
